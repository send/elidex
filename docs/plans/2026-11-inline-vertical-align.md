# Resolve signed vertical-align lengths at inline placement

G′b.2 Float follows the [Grid track plan](2026-11-grid-track-lengths.md) at 833a33ef (#745). PM 1035 F3 assigns the numeric vertical-align receiver to this child. Verify the implemented G grammar, N evaluator and C1c typed projection/assignment at the implementation head. Source paths below describe 833a33ef. Float, clear and visibility keep their existing behavior.

## §1. Connect both declaring paths to the line formatter

The stylesheet path in elidex-css declaration/misc.rs and the registered FloatHandler in elidex-css-float each parse vertical-align. Converge them on one engine-independent keyword-or-signed-length-percentage grammar. Delegate its numeric branch to G's strict length-percentage parser with complete consumption and T's receiving-property reparse. Retain the eight represented keywords. Convert absolute and context-dependent units once in the element's computation context. Store N's simplified, signed result and any outstanding percentage dependency on the existing VerticalAlign property in ComputedStyle. Remove the eager percentage evaluation in elidex-style resolve/mod.rs and the registered writer's baseline fallback for valid calculations.

Make both writers, FloatHandler's getter, explicit inherit and the elidex-css-anim apply dispatcher use C1c's typed property projection and assignment. Preserve existing supported scalar animation and discrete keyword selection. Project percentages and mixed values before and after layout without converting them to used pixels. The public computed-value branch serializes that projection; C2 owns generic mixed interpolation.

Emit inline owner start/end boundaries during collection. At wrapping, retain an owner fragment on each occupied line, including empty spans and owners containing only descendants. Give each owner its own strut and layout bounds, and each atomic inline its margin box. Apply N's signed offset relative to the parent's baseline in logical coordinates, toward line-over for positive values. Include each owner's aligned bounds once when calculating line extents, baseline and next-line origin. [CSS Inline §2.2](https://drafts.csswg.org/css-inline-3/#line-layout) and [§5.3](https://drafts.csswg.org/css-inline-3/#inline-height), including empty inline boxes under [CSS 2 §10.8](https://drafts.csswg.org/css2/#line-height)

Carry the owner's LineHeight past inline/styled_run.rs through font selection. Use a common used-line-height producer at the metric lookup in elidex-shaping/src/measurement.rs. Resolve normal from used-font ascent, descent and line-gap metrics under the same line-spacing policy, number from the owner's font size times the multiplier, and computed length directly. Use the same result for the owner's alignment bounds and as N's percentage basis. For a glyphless owner use its first available font's strut. [CSS Inline §5.1](https://drafts.csswg.org/css-inline-3/#line-height-property) and [CSS2 §10.8.1](https://drafts.csswg.org/css2/#leading)

Publish each text or atomic member's final logical block offset from its line origin in elidex-ecs/src/components/inline_flow.rs. Keep the source line identity, origin and baseline independently. Bidi reordering carries each member's offset with it. Both visual and logical iteration in elidex-render/src/builder/inline_flow.rs consume the member placement. Static atomic reconciliation, relative/sticky atomic targets and client rectangles likewise use the layout placement once. In inline/pack/boxes.rs store each wrapped descendant’s fragment border rectangles relative to its layout-owned border-box origin, which follows atomic subtree translation. In elidex-dom-api/src/element/layout_query.rs project those rectangles from the current origin when serving getClientRects(). [CSSOM View, getClientRects() step 3](https://drafts.csswg.org/cssom-view-1/#dom-element-getclientrects)

In inline/pack/fragment.rs select members, rectangles and positioned placements by source-line membership. Rebase the retained line origin into continuation coordinates and preserve its member offsets. Update the deferred-feature notes in inline/mod.rs and reconcile.rs for the supported numeric branch. Keep table-cell keyword dispatch in layout-table separate from the inline positioning operation. [CSS Inline §4.2.3](https://drafts.csswg.org/css-inline-3/#baseline-shift-property)

## §2. Crossing checks

| Crossing | Actual route | Required observation |
|---|---|---|
| Declaration × invalid winner | Built-in stylesheet and registered FloatHandler → T reparse → computed property → inline layout | Compare direct calc(10% - 5px) and var(--v) containing that expression for typed equality and equal baseline displacement. With an earlier 4px declaration, direct 10bogus or a valid value with trailing junk leaves 4px active. A winning var(--bad) with the same invalid input yields initial baseline. Separate number and ident tokens in var(--n)px remain invalid. Include signed literals, unitless zero, a negative calculation, and G’s deferred-unit and @supports controls. |
| Own line-height × direction | Styled inline and baseline sibling → actual positioned runs | With identical font metrics and parent line-height 60px, give the target inline used line-height 20px then 40px. Against a matched baseline control its calc(10% - 5px) lowers the glyph baseline by 3px then 1px. Measure the relative glyph baselines after line placement; reproject the unchanged numeric value each time. A +4px control raises the target by 4px; zero coincides. Repeat with an atomic inline of known baseline and with a vertical writing mode, observing the physical coordinate corresponding to line-over. |
| Owner × fragment geometry | Nested spans and atomic sibling → line extents and output | Give an outer inline a 4px raise and its child a 1px lowering. The nested baseline moves up 3px against a matched unshifted control. Wrap onto a second line and inspect positioned content, client rectangles and next-line origin. Include a shift exceeding the original line extent to force line growth; assert no clipping or extra shift at paint. |
| Publication × continuation | Same-group baseline and raised glyphs → persisted line → display list and client rectangles | Assert the signed baseline difference in display-list glyph coordinates for logical order and reordered bidi siblings. Verify static and relative/sticky atomic targets against their client and paint rectangles. On first layout wrap a nested span across two lines inside a narrow atomic beside a baseline control. Keep the parent baseline fixed with a tall strut. Against matched controls with identical insets, a 4px raise moves the atomic box, both public descendant fragment rectangles and both painted glyph baselines up 4px. Exercise static and positioned targets. Force a shifted member across a fragment boundary and verify it is emitted once with its source line and retains its offset from the rebased origin. |
| Empty owner × line growth | Populated lines with identical struts → next-line origin | Use identical fonts and 20px line-heights, a baseline glyph on each of two lines and an empty 20px inline on the first. Raising that empty owner by 30px advances the second line's origin by an additional 30px in block progression versus the unshifted control. Repeat with a descendants-only owner and check its child's shift is applied once. |
| Normal × font selection | Controlled font metrics → owner bounds and percentage placement | With font-size 10px and a distinct parent basis, select fonts with measured normal heights 16px and 14px. A 50% raise gives 8px and 7px against matching siblings. Repeat with a glyphless owner, observing its bounds and next-line origin. Check number 2 and length 20px both give 10px. |
| Declared × computed readback | Public stylesheet rule getter (elidex-dom-api/src/cssom_sheet.rs) and registered parsed-declaration serialization → reparse → actual layout | Before computation read back -4px and calc(10% - 5px) on both routes. Reparse each serialization and assert signed typed equivalence to the original. A var(--v) declaration retains its reference in declared readback. Assert its substituted mixed computed projection on a real target both before and after layout and compare placement with the direct declaration. |
| Projection × assignment | Computed component → inherit / public apply → used reader | An explicitly inheriting child with its own line-height uses the parent's typed percentage against the child's basis. Without inheritance the initial value is baseline. Apply a projected mixed value to a differently initialized inline, verify the signed result through actual placement, then restore a keyword through the same operation. Check existing table-cell top/middle/bottom/baseline behavior. |
