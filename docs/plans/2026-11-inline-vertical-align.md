## §1. Connect both declaring paths to the line formatter

The stylesheet path in elidex-css declaration/misc.rs and the registered FloatHandler in elidex-css-float each parse vertical-align. Converge them on one engine-independent keyword-or-signed-length-percentage grammar. Delegate its numeric branch to G's strict length-percentage parser with complete consumption and T's receiving-property reparse. Retain the eight represented keywords. Convert absolute and context-dependent units once in the element's computation context. Store N's simplified, signed result and any outstanding percentage dependency on the existing VerticalAlign property in ComputedStyle. Remove the eager percentage evaluation in elidex-style resolve/mod.rs and the registered writer's baseline fallback for valid calculations.

Make both writers, FloatHandler's getter, explicit inherit and the elidex-css-anim apply dispatcher use C1c's typed property projection and assignment. Preserve existing supported scalar animation and discrete keyword selection. Project percentages and mixed values before and after layout without converting them to used pixels. The public computed-value branch serializes that projection; C2 owns generic mixed interpolation.

In layout-block's inline collector and line packer carry the alignment owner for each inline box, including text-bearing spans and atomic inlines. At baseline-relative placement obtain the inline's own used line-height from its line-height and font metrics through the existing line-height resolution path. Evaluate the preserved numeric value against that basis with N. Apply positive displacement toward line-over and negative displacement toward line-under in the formatter's logical coordinates. Align a nested inline relative to its parent and move its contents together. Charge each ancestor shift once. Include shifted ascent/descent in line extents before finalizing the baseline and subsequent line origin. Publish consistent glyph positions, atomic box offsets and inline client/paint rectangles from that placement. Update the deferred-feature notes in inline/mod.rs and reconcile.rs for the supported numeric branch. Keep table-cell keyword dispatch in layout-table separate from the inline positioning operation. [CSS Inline §4.2.3](https://drafts.csswg.org/css-inline-3/#baseline-shift-property)

## §2. Crossing checks

| Crossing | Actual route | Required observation |
|---|---|---|
| Declaration × invalid winner | Built-in stylesheet and registered FloatHandler → T reparse → computed property → inline layout | Compare direct calc(10% - 5px) and var(--v) containing that expression for typed equality and equal baseline displacement. With an earlier 4px declaration, direct 10bogus or a valid value with trailing junk leaves 4px active. A winning var(--bad) with the same invalid input yields initial baseline. Separate number and ident tokens in var(--n)px remain invalid. Include signed literals, unitless zero, a negative calculation, and G’s deferred-unit and @supports controls. |
| Own line-height × direction | Styled inline and baseline sibling → actual positioned runs | With identical font metrics and parent line-height 60px, give the target inline used line-height 20px then 40px. Against a matched baseline control its calc(10% - 5px) lowers the glyph baseline by 3px then 1px. Measure the relative glyph baselines after line placement; reproject the unchanged numeric value each time. A +4px control raises the target by 4px; zero coincides. Repeat with an atomic inline of known baseline and with a vertical writing mode, observing the physical coordinate corresponding to line-over. |
| Owner × fragment geometry | Nested spans and atomic sibling → line extents and output | Give an outer inline a 4px raise and its child a 1px lowering. The nested baseline moves up 3px against a matched unshifted control. Wrap onto a second line and inspect positioned content, client rectangles and next-line origin. Include a shift exceeding the original line extent to force line growth; assert no clipping or extra shift at paint. |
| Projection × assignment | Computed component → inherit / public apply → used reader | An explicitly inheriting child with its own line-height uses the parent's typed percentage against the child's basis. Without inheritance the initial value is baseline. Apply a projected mixed value to a differently initialized inline, verify the signed result through actual placement, then restore a keyword through the same operation. Check existing table-cell top/middle/bottom/baseline behavior. |
