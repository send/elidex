## §1. Compute once and resolve against the painted box

Use the same corner grammar from the stylesheet declaration dispatcher (declaration.rs and declaration/misc.rs) and registered BoxHandler. A corner longhand takes one or two nonnegative length-percentages. A single component supplies both axes. For border-radius expand the horizontal and optional slash-separated vertical lists independently in TL, TR, BR, BL order using the CSS one-to-four expansion. Absent a slash, copy the expanded horizontal list to the vertical list. Validate the entire declaration before publishing any longhand. Reparse substituted shorthand and longhand through T using the receiving grammar. Preserve authored declaration readback. Delegate supported unit classification and contextual length conversion to G and simplification and evaluation to N. Retain an unresolved percentage dependency, including the nonnegative range until its basis is known. [CSS Backgrounds §4.1](https://drafts.csswg.org/css-backgrounds-3/#border-radius)

Replace the four scalar border_radii in ComputedStyle with four computed horizontal/vertical pairs. Route BoxHandler, the built-in elidex-style resolve/box_model writer, computed getter, explicit inherit and css-anim/apply through C1c typed projection and assignment. Keep the pair at declaration, computed and animation endpoint boundaries. Use existing scalar sampling for supported components and C2 for generic mixed interpolation. The DOM/harness computed corner getter projects the pair even after paint. Layout owns the border-box reference; paint evaluates horizontal against width and vertical against height each time the geometry changes.

Resolve all four pairs before applying the common overlap reduction factor from the minimum side-length-to-adjacent-radii-sum ratio (bounded above by one, ignoring zero sums). Derive inner radii component-wise from the reduced outer radii: subtract the corresponding horizontal and vertical border thickness, flooring each at zero. Carry pairs through walk.rs, paint::compute_inner_radii, background shapes, border rings, overflow/background clips, shadows where they take corner geometry, display_list.rs and vello_backend.rs. Use elliptical paths for fill, ring and clip, including per-side colored borders. A zero axis makes that corner square. For sliced decorations resolve against the unbroken box and square both axes at internal breaks; cloned decorations use each fragment's box. [CSS Backgrounds §§4.2–4.5](https://drafts.csswg.org/css-backgrounds-3/#corner-shaping)

For width/height, min/max constraints, four margins and paddings and both gaps inventory declaration entries, style writers, C1c typed projections and actual used readers at implementation HEAD. Reuse C1a public geometry dispatch, C1b optional-reference/formatting-context operations and C1c field assignment. Preserve per-property keywords and signed or nonnegative ranges. Keep the C1 table-role and indefinite/cyclic-reference branches. For border widths migrate the numeric length branch only, retain existing keyword mapping and style-dependent zero, and exercise built-in and registry resolution. The declared keyword fidelity slot retains its existing scope.
