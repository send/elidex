## §1. From an accepted break to a page

At 0e412f94, block/children/stack.rs ends a fragment at a forced break-before or break-after by returning a child position. That position cannot distinguish an ordinary forced page break from a request for a particular page side. At the pagination entry, layout/mod.rs::layout_paged chooses one default content rectangle and infers blankness from the resulting box dimensions. The interleaved builder independently seeds its count pass and repeats the dimension check when replaying the input tokens.

Have the accepting layout boundary return its source progress and a distinct typed break event. Report only the winning boundary after forced-value combination, including propagated before/after values in flow order. Events describe ordinary page advancement or the requested side in the document’s page progression. Keep the source token solely responsible for item progress. A nested column boundary consumed by the column formatter cannot itself advance the page. Propagate a page-directed break through enclosing fragmentation contexts to the page owner; preserve the source boundary and consume the event exactly once there.

Build a run-owned ordered page plan. For the next content page, use the next page number, progression and the pending boundary event. A side already satisfied yields content immediately. If the side requires an intervening blank, append one blank entry with its own selected geometry, advance the page number, and resume content using the same source progress. Clear the side requirement after applying it. Ordinary overflow and plain forced page breaks insert no intervening blank. Before the first entry, resolve the propagated initial request against document progression and seed one run identity with the first printed side. Pass that identity to selector matching and 3b.1’s first-area preparation, then advance sides from it throughout the run. In LTR the default and recto start on the right. An initial left or verso request starts printed page 1 on the left, matching both :first and :left. The next printed page is right. Use distinct first-left and first-right geometry and verify viewport, page and pages counters and absence of a leading blank for each initial request. Resolve logical sides from progression (CSS Page §4.2 and CSS Break §4.3).

Determine blank/content identity before selecting geometry from the immutable 3b.1 snapshot. Each entry owns its page number, kind, selected sheet, margins, origin and area; a content entry also records the input progress and committed outgoing coverage. Blank entries reserve a physical page and contribute to page counters, with no body layout, body-counter increment or source consumption. Content can have zero area or no visible ink. Only the boundary event can cause a forced blank entry.

The count pass lays out content with that entry's own width, origin and block extent, retaining the document viewport computed from the first page. Use max(1 CSS px, used fragmentainer block extent) only for fragmentation progress. Keep the actual selected sheet dimensions, origin and area in the entry and in downstream geometry. This rule does not enlarge a zero inline dimension. Remove the two page-entry shortcuts that drop a nonempty document for nonpositive content dimensions. Preserve the empty-root return and existing generation/provenance behavior. Require each content step to exhaust its input or commit progress under the 3b.2 contract. A blank advances page state once at fixed source progress. Test natural termination below MAX_FRAGMENTS so that reaching the cap cannot mask stalled content.

Have layout_paged and the interleaved count path use the same plan producer. Replay a content entry using its recorded input, geometry and a fresh paint generation. A blank entry carries its own selected margin-box inputs but has no current-generation body output. Derive total pages from the completed plan. Replace both dimension-based blank checks. Keep generic fixed-fragmentainer clients on their existing contract. Hand the entries to 3b.4 for publication by both builders.

### Boundary ownership and replay

In block/children/stack.rs the forced-before and nonterminal forced-after branches must preserve the selected boundary value with the outcome. The first-child before and last-child after propagation fields describe the enclosing boundary; route them through the same winner selection when that boundary is reached. Combine adjoining after/before declarations before publishing an event. In the supported LTR fixture, A requests break-after:right and B requests break-before:left at the same boundary. The later side request selects left, so B immediately occupies page 2. Reverse the two requests and B occupies page 3 after a blank. Select geometry again for that blank with its own page number. Replaying either recorded plan must produce exactly the recorded entries without firing the accepted event a second time.

The child-boundary alternative of the 3b.2 typed token identifies the sibling boundary and resumes on its far side. Route it to the owning formatter through keyed nested continuations. Only the event carries the requested side. For before-only, after-only and adjoining requests, record accepted boundary identities in order and B’s first contribution after the break, including across an inserted blank. Put a later forced break inside B and require it to fire exactly once in both count and replay.

Extend the shared chooser’s winning result with the combined break requirements and that candidate’s proposed intervals. Block supplies adjoining child values, Flex the values at a line boundary and Grid those at a row boundary, in flow order. Definitive layout returns that result with actual admitted item outcomes, including partial and terminal intervals and keyed nested tokens. Preserve deferred child continuations. Probes and rejected candidates publish no event, coverage or generation-visible boxes. At internal Flex line and Grid row boundaries exercise side-after plus plain-page-before and the reverse: the side requirement survives both. With competing side values the later side wins. Check accepted events, actual emitted siblings and coverage.

In a paged multicol place P and Q inside one nested child, with room for another column on page 1 and break-before:right on Q. Definitive fill returns the page event together with interrupted progress before filling the spare column. For sequential and balanced fill require P on page 1, blank page 2, and Q first on page 3. Inspect P’s committed interval and Q’s exact keyed resume state at page 1 exit, across the blank and at page 3 entry in count and replay. Assert no event from balancing probes. With break-before:column instead, the column owner consumes the event and Q starts in the spare column on page 1.

Use a fresh nonzero generation for each definitive content layout. Keep blank entries independent of stale body boxes written by the preceding content page. The existing provenance test layout/tests/provenance.rs::a_zero_write_paged_early_return_leaves_the_phase_alone uses a nonempty DOM with margins exceeding the sheet. Update that fixture for the changed behavior: its zero-area content page reaches layout and the first actual store write invalidates the previous screen geometry. Keep a distinct empty-root, genuinely zero-write case and assert the published screen state survives through both paged entry points. Entry into pagination alone does not invalidate a store.

## §2. Crossing checks

| Crossing | Producer → consumer | Distinguishing observation |
|---|---|---|
| Break event × selection | Chosen before/after side → pagination | In left-to-right progression, page 1 contains A. Request right before B or after A. Page 2 is blank and page 3 resumes B. Request left instead: page 2 contains B. A plain forced page break also produces two content pages. Inspect each entry’s input and exit, page numbers, body and blank-only margin-box selection. |
| Geometry × progress | Selected page style → layout and count | Follow a valid 100×60px declaration with a negative literal height (declaration rejected), then separately with calc(-1px) direct and substituted (winning height clamps to zero). Publish the true 60px or 0px height. In the zero case use 1px for block progress and a usable next page. Repeat with a positive 100px sheet whose margins consume all its block extent. Record actual area, effective progress extent, completed content and the final empty complement. |
| Progress × replay | Count entries → interleaved body and margins | Capture each page before another layout overwrites entity boxes. Both passes independently satisfy the expected words, intervals, page IDs and origins. With A on page 1, blank page 2 and B on page 3, require body only on 1/3, the blank margin box only on 2, page numbers 1/2/3 and total 3 throughout. A zero-height content page must still match its content selectors. |
| Invalidation × selection | Changed first-page rule → fresh plan | Change page-local margin input to make two 35px boxes cease to fit on a 100px-high sheet (10px → 20px vertical margins). The entry count goes from one to two and origins move with the selected margins. Hold the prior plan through the rerun and inspect both plans independently. |

Drive the stylesheet through the paged entry with a default 200×100 sheet and 10px margins. Give :first a 140×100 sheet with 20px left and 10px other margins. Keep :blank at 120×60 with 5px margins. Use A on page 1 and a right request before B. For each body use distinct four-word text with deterministic 40px word advances and 5px spaces, with no body padding or indent. The first area is 110×80 at (20,10), fitting two words per line. Page 2 has a 110×50 area at (5,5), the blank margin marker and no body output. Page 3 has a 180×80 area at (10,10), fitting all four B words on one line. In count and paint separately capture each entry’s area, first word’s physical inline start and line-top, ordered line contents and source intervals before boxes are overwritten. Keep the document viewport fixed to the selected first area on every page. With a left request require two content pages and retain the original three-entry plan. Inspect public drawing records in 3b.4.
